# Storyboarder：多线分镜、绘画与 ComfyUI 一体化设计

日期：2026-09-22  
状态：用户已选择第 2 张「绘画工作台」，并确认独立原型的画面/地图切换可用。正式应用已接入镜头级路线、分支、汇合和持久化，并完成隔离项目的保存重开及进程重启验证；ComfyUI 执行尚未接入。  
范围：延续当前 Windows 桌面应用、用户手绘分支结构与现有绘画能力。不是重建项目或启动存储迁移。

## 1. 产品目标与第一版边界

作者可以组织共用开头、多个后续走向、并行故事线和备选拍法；进入任意镜头绘画、指定参考、生成候选，最终明确选择播放与导出的顺序。

同一个项目提供地图、绘画、播放工作视图。用户已选择第 2 张概念稿作为默认方向：左侧故事结构、中央绘画、右侧参考与生成、底部当前路线。原型用于验证交互，不替换正式绘画编辑器或修改存档格式。

第一版不包含条件脚本引擎、无限循环剧情、自动推理剧情状态、自动修复连续性、任意 ComfyUI 工作流兼容或文档格式迁移。这里的分叉和汇合是结构关系，不声称 AI 能自动理解剧情状态。

## 2. 必须区分的关系

| 类型 | 含义 | 展示 | 播放处理 |
| --- | --- | --- | --- |
| 剧情分支 | 从共同节点进入不同后续事件 | 有名称的有向分支 | 手动选择路径，未解决分叉不自动选边 |
| 并行故事线 | 多组故事内容的组织关系 | 命名泳道或目录 | 另外编排交叉剪辑顺序；泳道位置不等于发生时间 |
| 创作备选 | 同一个叙事位置的不同拍法或段落版本 | 备选组，明确当前采纳项 | 导出采用的方案，其他版本保留 |
| 生成候选 | 同一个镜头的一次或多次出图结果 | 镜头内部候选区 | 采纳到独立生成图层，不自动创建故事节点 |
| 生成依赖 | 当前镜头参考其他镜头/角色/场景 | 参考面板及范围提示 | 不作为故事播放边 |

首版允许多入边汇合，禁止自环和循环。汇合节点自行指定生成参考，不随机继承某一个父节点的画面。

## 3. 工作台交互

### 地图

沿用 Studio 主题及现有导航。中央为可缩放平移的故事地图；默认节点代表段落，显示封面、名字、镜头数，必要时展开镜头。长故事可折叠段落，不一次展示全部画面。

主要动作：添加后续、从此分支、连接已有段落、复制为独立段落、双击编辑。选择节点在右侧显示上下文；底部显示当前播放路线。连线以箭头和标签表达含义，颜色不是唯一提示。

拖动节点只保存布局坐标。删除连接不删除镜头或图片。删除段落前显示引用范围；资产清理另行处理。共享节点明确显示“被多条路线引用”，编辑会影响引用它的路线；复制为独立段落后，镜头内容独立，角色/场景资产仍可复用。

### 绘画

中央复用现有镜头画布和全屏编辑器；左侧为可折叠结构导航，右侧为图层、参考、生成。面包屑显示路线、段落和当前镜头。

草图、背景与生成结果保持不同图层。生成候选要明确采纳，不能替换手绘原稿。切换地图/镜头前处理未保存笔画，不无提示卸载编辑器。模型和工作流的高级参数收进扩展面板。

### 编排

命名故事线展示各自内容，另有一条显式“当前剪辑”。并行线之间的交叉顺序由作者确定。路线预览和导出消费同一份解析结果。

播放器需要确定顺序；未选择的备选、悬空引用和未解决的分叉应定位到问题处。允许切换路线查看，但不能通过改写全项目镜头数组来实现筛选。

### 视觉基线

复用现有 CSS token，不新增一套相同主题配置：

- 背景 #07090d；面板 #10151d；画布 #111720；边框 #26303d。
- 正文 #f4efe4；辅助文字 #9f9a8f；选中与主要操作 #d6a84f。
- Segoe UI / PingFang SC / Microsoft YaHei；6px/8px 圆角。
- 尊重用户选择的其他现有主题，不强制改回 Studio。

概念图用于判断布局，不是功能截图。图中的“ComfyUI 已连接”、镜头编号、剧情文案和候选图都是示例。精确连线、选择同步、名称以及可访问性以实现与测试为准。

## 4. 根据当前代码划定工程边界

| 现有实现 | 证据 | 设计影响 |
| --- | --- | --- |
| 主工作区只有 strip/grid | frontend/src/App.tsx，BoardWorkspace | 在现有入口增加视图，不建立第二套应用壳 |
| 单镜头画布与可编辑绘画文档 | CanvasBoard.tsx、FullDrawingEditor.tsx | 复用用户正在开发的绘画功能；故事图不是绘画画布的对象层 |
| 全局 Project.shots 数组 | storyboard_tool/models.py、frontend/src/types/project.ts | 镜头资产继续按稳定 shot_id 归属 |
| Shot.sequence 是文本 | storyboard_tool/models.py | 不可当作已存在的段落实体或关系表 |
| BoardStrip/Grid 直接读全项目数组 | frontend/src/components/BoardStrip.tsx、BoardGrid.tsx | 未来传入路线解析后的展示序列；全局列表不随路线切换改变 |
| 重排接口要求完整镜头集合 | project_manager.py、ProjectContext.tsx | 分支内移动不能复用全局重排的写语义 |
| board_range 按全局位置升序去重 | board_range.py、export_service.py | 现有范围导出不是路线导出；不能表达任意剪辑顺序和重复引用 |
| continuity 已保存直接镜头依赖 | models.py、generation_service.py | 可复用作生成参考，不能替代故事拓扑 |
| Layout2 存档有成员白名单 | project_document.py | 新图数据必须进入保存/恢复/打包/转换路径，不是单独写个 JSON 即完成 |
| stable_diffusion 是外部 handoff | generation_service.py | 没有据此确认 ComfyUI 执行器；“发送请求”不能报告为“已生成” |

当前仓库包含用户尚未提交的绘画、Fabric、存储、API 与预构建 bundle 改动。本轮保留这些内容，不按历史 PROJECTCONTEXT 推断实现状态；Layout2 在当前源码中已经存在。

## 5. 后续数据职责设想（不等于当前持久化合同）

- Shot：现有镜头内容、图层及资产的唯一归属。路线不复制整份 Shot 作为第二个可写真相。
- Sequence：有稳定 ID 的段落，含有序镜头引用。第一片可从现有线性列表生成默认段落的只读视图。
- StoryGraph：段落连接与布局。布局字段不参与播放排序。
- StoryLine：命名组织集合；不隐含选择、同时发生或时间轴坐标语义。
- AlternativeGroup：指定叙事位置的互斥方案与采纳选择。
- Cut：明确的有序出现项；用 occurrence_id 区分同一个 shot_id 的多次出现。
- GenerationRequest：绑定 project/session、shot_id、输入快照和工作流版本；UI 当前选择不是结果回写目标。

持久化前需要明确 schema 版本、缺失字段兼容和回滚/恢复策略。旧文档打开时仍显示原线性顺序；禁止在读文件时悄悄重排或自动迁移。

## 6. ComfyUI 接入合同

先做经过验证的有限工作流：草图生成、局部重绘、参考图修改。工作流通过显式输入映射接收草图、遮罩、角色/场景参考与输出尺寸；高级节点图仍可访问。

后端负责连接检查、能力检查、任务 ID 映射、进度、取消、重连后结果查询与候选入库。ComfyUI 输出只进入候选目录，采纳动作再写独立生成图层。

任务必须保存输入版本。用户在生成时换镜头、换分支或修改草图，结果仍回原镜头；输入已改变时标记过期候选，不自动声明 current。分支参考在创建请求时确定，后续修改不能改变在途请求。仅保存可变参考文件路径不等于内容快照，需要在执行接入前解决。

取消只针对属于本项目的任务；避免把服务级“中断”错误当成单任务取消。模型缺失、工作流不兼容、连接中断都应有明确状态，不伪造完成。

生成结果的采纳需要与项目保存一致：已采纳的候选不得被 inbox 重放覆盖；保存失败后必须可以恢复准确的候选和镜头 metadata。这是实际接入前的工程前置条件。

## 7. 实施顺序与验收门槛

1. 选定布局，确认剧情分支/并行线/备选的交互差异；完成不改文档格式的可交互演示。
2. 提取有边界的纯路线解析与校验逻辑。先验证分叉选择、汇合、缺失引用、循环拒绝及确定的导出顺序。
3. 接入故事关系的持久化与撤销，覆盖旧文档、保存重开、保存失败、恢复、Layout1/2。再启用图编辑写入。
4. 将镜头条/网格/播放器绑定路线视图；保留原全局重排行为，仅增加明确的路线编排操作。
5. 完成生成采纳的提交与恢复协调，再接入有限 ComfyUI 工作流和异步任务 UI。
6. 做路线导出与连续性提示，验证完整创作流程后再扩展复杂自动化。

第一版用同一示例验收：

- 共用开头 → 三个后续 → 两条路径汇合，每段含两张分镜。
- 编辑共用段落时引用路线同步；复制独立段落后不串改。
- 拖地图不改变播放；分支内重排不改变其他路径。
- 两条并行线组成一个明确交叉剪辑。
- 生成四张候选仍是一个镜头；采纳第二张后重复拉取不换回第一张。
- 生成期间换分支、编辑输入或删除镜头，不发生串写。
- 保存失败后重试，准确恢复原采纳项；保存重开保持结构和路线。
- 两条路线分别导出，不覆盖不同选择的输出；旧线性项目照常工作。

## 8. 前期工程结果（正式工作台集成前）

已修复 board_range 对超过三张的非连续选择仅使用首尾命名的问题。例如 1,3,5,9 与 1,4,7,9 之前生成同一路径。

现在仅对长非连续选择添加完整标准化集合的 BLAKE2s 64 位摘要。短选择、连续范围及整项目名称不变；相同集合和等价输入保持同名。摘要使碰撞风险极低，但不是数学上的唯一编码，也不是历史版本管理。对同一选择重新导出仍会更新同一输出。

旧名称导出文件不会被迁移或删除；这类旧范围输出需要重新导出一次，新“打开导出”才能按新名称定位。

新增验证包括不同内部选择不同名、等价输入同名、增加未选镜头不改名，以及实际 CSV 双文件共存且原项目不变。

### 发现但未交付的生成问题

reconcile_results 会把 completed 请求重新改为 needs-review，pull_results 又取第一个候选，可能覆盖人工采纳的第二个候选。

曾实验性添加终态跳过并以 10 个跨 Layout1/2 测试验证正常流程。但独立复核发现：accept 先写图层与 completed marker，调用层随后 autosave；若 autosave 失败，mutate_project 仅回滚内存，跳过 completed 将阻断后续 metadata 恢复。

因此实验 guard 已从实际仓库撤回；对应新增测试也从仓库移除并保留在本轮设计资料目录。没有把该问题标为已修复。后续应协调采纳、终态与 autosave 的提交/恢复，而非孤立改变一个状态判断。

## 10. 正式工作台第一片：实际实现合同

当前以镜头作为图节点，不引入 Sequence、StoryLine、AlternativeGroup 或 Cut 表。以上章节中的段落折叠、独立备选组、交叉剪辑和路线导出仍是后续设计，不能当作已交付功能。

- Draw 复用 CanvasBoard / Fabric 全屏编辑器；Map 显示真实镜头图；Play 按当前路线和镜头时长预览。All boards 保留原网格、镜头条、全局排序及批量操作。
- 路线保存在既有 settings.json 的 story_graph 字段，包含 version=1、revision、active_route_id、routes 与 positions。routes 保存有序 shot_id 引用；连线由相邻引用推导，布局不决定播放顺序。
- 旧项目没有此字段时，只读派生原线性主线；打开文件不会自动写图或迁移格式。首次修改故事结构后才保存图。Layout1 文件夹、Layout1 .sbd 与 Layout2 复用既有保存/打包路径。
- Branch 共享当前路线至选中镜头的前缀，并添加一个新空镜头作为分支结尾。Join 把已有镜头追加为当前路线结尾，不自动复制它的后续路线。共享镜头的画面和信息只有一份；修改会影响所有引用路线。
- 图校验拒绝重复路线 ID、路线内重复镜头、缺失引用、未归属镜头、非有限坐标以及任意路线连线合并后产生的循环。过期 revision 返回 409，避免覆盖新状态。
- 新增/复制镜头只扩展当前路线；删除镜头会清理所有路线引用。全局排序不改变已保存的路线顺序。删除撤销携带图快照，同事务恢复共享引用及布局；图结构编辑自身暂不提供多步撤销。
- 打开绘画编辑器时，切镜头、切路线和结构编辑受保护。Map/Draw 切换保持编辑器挂载；先保存绘画或明确关闭编辑器，再执行受保护操作。绘画中暂缓项目自动保存，避免保存未提交笔画的假象。
- 前端故事图类型/API/状态适配独立于绘画对象；后端校验集中在 story_graph.py。图写入、分支创建和删除撤销受现有项目锁与持久化事务保护。

右侧继续使用原镜头详情与高级功能，不显示假的 ComfyUI 已连接状态。生成采纳的事务问题、真正 ComfyUI 执行和按路线导出未在此片实现。现有导出仍按全局镜头范围工作。

生产验证使用仓库虚拟环境及独立本地服务、测试项目；不修改用户真实项目。验证截图与临时脚本保存在 Codex 外部资料目录，不加入生产源码。

### 集成中发现的直接相关修复

- Layout2 自动刷新旧逻辑从隐藏 work/project.json 重开时丢失便携项目根目录，导致真实图片被错误解析到 work/Images/Shots。刷新现在显式保留原 project_root；回归覆盖 PNG 导入、保存、刷新、HTTP 图片访问与再次重开。
- 新工作台默认收起原来的图层/队列浮窗，避免遮住绘画；修复选中路线卡片类名，确保缩略图布局一致。
- 从 All boards 回到路线视图时，先对齐选中镜头所属路线；地图 Enter/Space 选择真实镜头，不允许键盘造成未保存的节点位移或误触全局删除。
- 当前 Fabric 默认中心原点；新载入底图和新建空白底板现在显式使用左上角原点，避免只覆盖四分之一画布。已有绘画文档的对象位置和原点不自动迁移。

新绘画文档把初始底图的原始图片快照嵌入 Fabric JSON，不再引用会被保存操作覆盖的预览 URL；保存后的合成预览不是编辑图层的底图来源。这会增加可编辑 JSON 的大小，但避免重开缩小、笔画重复和新底图对旧服务端口的依赖。已有绘画文档中保存的绝对 HTTP URL 与对象位置不自动改写；旧文档如果已丢失原底图，不能从合成预览无损反推恢复。

原生绘画舞台根据逻辑画布宽高比，同时适配可用宽度和高度；横版/竖版只改变显示缩放，不改变 Fabric 位图尺寸。
